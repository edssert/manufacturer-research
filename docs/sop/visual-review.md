# SOP: 제품 이미지 육안 검수

자동 검사가 판단할 수 없는 항목을 사람이 확인하는 절차다. 해시·치수·알파 채널은
스크립트가 검사하지만, "이 이미지가 이 제품의 쓸 만한 대표 이미지인가"는 눈으로만
판단할 수 있다. 근거는 [`AGENTS.md`](../../AGENTS.md)의 원문·이미지 정책과
[ADR-0004](../adr/0004-runtime-image-content-policy.md)다.

## 언제 수행하나

- 런타임 이미지를 추가·교체·삭제했을 때
- [런타임 미디어 SOP](runtime-media.md)의 `apply`를 실행한 뒤
- 대표 이미지 예외(`officialSubstitutions`, `maskedDerivatives`)를 추가·수정했을 때
- 새 제조사나 새 시리즈를 카탈로그에 처음 넣을 때

## 1. 그리드 개관

전체 이미지를 한 화면에서 비교한다.

```powershell
python scripts/montage_check.py check.png
```

생성된 PNG는 검수용 산출물이므로 런타임 자산으로 커밋하지 않는다(`.gitignore`가
`montage_check_output.png`를 제외한다. 다른 이름으로 만들었다면 검수 후 지운다).

그리드에서 다음을 찾는다.

- 다른 이미지 대비 유난히 크거나 작은 제품
- 흰 배경과 섞여 프레임처럼 보이는 이미지
- 로고·텍스트·배지가 남아 있는 이미지
- 같은 시리즈 안에서 촬영 각도나 스케일이 튀는 이미지

## 2. 개별 판정

의심 항목은 원본 해상도로 열어 다음 순서로 판정한다.

### 2.1 제품 정체성

- 이미지의 제품이 레코드의 모델과 실제로 같은가
- 무관한 시리즈 이미지나 상위 모델 이미지를 대신 쓰고 있지 않은가
- 변형 모델 별칭을 썼다면 [`config/runtime-media-overrides.json`](../../config/runtime-media-overrides.json)에
  근거가 기록되어 있는가

### 2.2 금지 콘텐츠

다음이 보이면 대표 이미지로 쓰지 않는다. 목록의 단일 원본은
[`config/asset-policy.json`](../../config/asset-policy.json)의
`normalization.representativeMedia.prohibitedContent`다.

- 수상 배지, 홍보 마크, 텍스트 오버레이, 기능 설명 콜아웃, 무관한 시리즈 이미지

추가로 다음도 대표 이미지가 아니다.

- 액세서리 레일·브래킷·포장이 주가 된 이미지
- 설치 현장 사진, 소프트웨어 화면
- 제품 일부만 잘린 크롭

### 2.3 이미지 품질

픽셀 크기만 보고 통과시키지 않는다. 실제로 확대해 확인한다.

- 초점이 맞고 그릴·단자·로고 같은 디테일이 읽히는가
- 저해상도 원본을 늘린 업스케일 흔적(뭉개짐, 링잉, 블록 노이즈)이 없는가
- 압축 아티팩트가 제품 경계에 두드러지지 않는가
- 크롭이 제품을 자르지 않고, 여백 비율이 같은 시리즈 안에서 튀지 않는가

### 2.4 배경과 스테이지

- 배경이 순백이거나 투명이고, 흰 스테이지와의 이음매가 보이지 않는가
- 비백색 배경 사진을 누끼로 오인하지 않았는가
- 제조사 원본에 포함된 그림자를 임의로 제거하지 않았는가
- 투명 렌더에 인공 drop-shadow를 추가하지 않았는가

원본이 이미 깨끗한 흰 배경이면 투명화는 필수가 아니다. 무리하게 누끼를 다시 만들지
않는다.

### 2.5 파생본 검수

로컬 마스크 파생본은 원본과 나란히 놓고 확인한다.

- 지운 영역 밖의 픽셀이 그대로인가
- 제품 형상·단자·그릴·로고·비율이 바뀌지 않았는가
- 마스크 경계에 잔상이나 색 번짐이 없는가
- 생성형 편집으로 없던 픽셀을 만들지 않았는가

## 3. 화면에서 확인

이미지는 단독으로 보는 것이 아니라 카드와 상세에서 본다.

```powershell
npm run build
npm run preview
```

`http://127.0.0.1:4173/manufacturer-research/`에서 확인한다.

- 카드 그리드에서 같은 시리즈 제품의 시각적 크기가 고르게 보이는가
- 카드 미디어 박스 안에서 제품이 잘리거나 지나치게 작아 보이지 않는가
- 상세 모달의 다중 뷰 선택기가 모달 폭 안에서 동작하는가
- 이미지 확대 pane에서 디테일이 견딜 만한가

전체 화면 검수 절차는 [브라우저 검수 SOP](browser-review.md)를 따른다.

## 4. 판정 결과 반영

| 판정                | 조치                                                                                       |
| ------------------- | ------------------------------------------------------------------------------------------ |
| 통과                | 그대로 둔다                                                                                |
| 금지 콘텐츠 포함    | [런타임 미디어 SOP](runtime-media.md) 1절의 선택 순서를 다시 적용하고 예외를 기록한다      |
| 품질 미달           | 더 나은 공식 원본을 다시 확보한다([원문 수집 SOP](source-intake.md))                       |
| 제품 불일치         | 레코드의 이미지 경로를 바로잡고 잘못된 자산을 정리한다                                     |
| 판단 보류           | 확인 가능한 근거가 나올 때까지 교체하지 않고, 무엇이 불확실한지 기록한다                   |

이미지를 교체·삭제했다면 관련 manifest를 같은 커밋에서 갱신하고 다음을 실행한다.

```powershell
npm run test:audit:assets
npm run verify
```

## 체크리스트

- [ ] 그리드 개관에서 이상 항목을 추렸다
- [ ] 의심 항목을 원본 해상도로 확대해 판정했다
- [ ] 금지 콘텐츠가 남아 있지 않다
- [ ] 업스케일·초점·크롭 문제를 확인했다
- [ ] 배경과 흰 스테이지의 이음매를 확인했다
- [ ] 파생본의 편집 범위를 원본과 대조했다
- [ ] 실제 카드·상세·확대 화면에서 확인했다
- [ ] 검수용 생성물을 저장소에 남기지 않았다
