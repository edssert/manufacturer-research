# SOP: 브라우저 화면 검수

jsdom 테스트는 DOM 계약과 상태 전이를 검증하지만 실제 렌더링·폰트·스크롤·터치·확대는
검증하지 않는다. 화면을 바꾼 변경은 실제 브라우저에서 확인한다. 근거는
[`AGENTS.md`](../../AGENTS.md)의 프론트엔드 규칙과 [`DESIGN.md`](../../DESIGN.md)의
접근성·상호작용 계약이다.

## 언제 수행하나

- CSS, 뷰, 컨트롤러, 모달, Split View, 내비게이션을 변경했을 때
- 카드 스키마나 표시 필드를 바꿨을 때
- 런타임 이미지를 교체했을 때([육안 검수 SOP](visual-review.md)와 함께)
- 릴리스 전([릴리스 체크리스트](../release-checklist.md))

## 0. 준비

배포와 같은 산출물을 본다. `preview`는 소스가 아니라 `dist/`를 서빙하므로 먼저
빌드한다.

```powershell
npm run build
npm run preview
```

주소는 `http://127.0.0.1:4173/manufacturer-research/`다.

## 1. 데스크톱

기준 폭 1440px에서 시작한다.

- [ ] 상단 브랜드 바와 도메인 탭이 의도한 높이와 정렬을 유지한다
- [ ] 도메인 탭의 현재 위치가 텍스트·하단선·카운트 배경으로 함께 표현된다
- [ ] 검색·정렬·초기화·필터의 위계가 유지된다
- [ ] 시리즈 헤더가 하나의 중앙 프레임을 공유하고, 카드 행이 그 프레임 왼쪽에서 시작한다
- [ ] 제품 개수가 항상 같은 오른쪽 정렬 슬롯에 있다
- [ ] 카드 폭이 고정되어 있고, 폭을 줄이면 카드가 늘어나지 않고 열 개수만 바뀐다
- [ ] 제품 이미지·모델명·SPL·앰프 관계의 시작선이 카드 간 동일하다
- [ ] 카드 정보 위계·라벨·단위·글자 크기·여백이 제조사와 제품 유형에 상관없이 같다

## 2. 모바일과 반응형

320px, 768px, 1440px과 그 사이의 전환 구간을 확인한다.

- [ ] 320px에서 가로 페이지 스크롤이 생기지 않는다
- [ ] 200% 확대에서도 핵심 기능을 쓸 수 있고 가로 스크롤이 생기지 않는다
- [ ] 860px 경계를 넘나들 때 Split View와 모바일 전체 교체 스택이 깨지지 않는다
- [ ] 모달이 열린 상태로 경계를 넘어도 화면과 URL이 함께 재구성된다
- [ ] 상세 모달의 다중 뷰 선택기가 모달 폭 안에서 가로 스크롤되고 페이지 밖으로 넘치지 않는다
- [ ] 사양 표가 좁은 폭에서 읽히는 열 구조를 유지한다

## 3. 상세와 관계 이동

- [ ] 카드를 선택하면 상세 모달이 열리고 배경이 잠긴다
- [ ] 데스크톱에서 관계 항목을 선택하면 두 pane이 나란히 열린다
- [ ] 모바일에서는 상세가 교체되고 내부 뒤로가기로 복귀한다
- [ ] pane을 여러 번 교체해도 브라우저 이력이 불어나지 않는다
- [ ] 이미지 확대 pane에서 Escape가 확대 → 관계 pane → 전체 모달 순으로 한 단계씩 닫는다

## 4. 키보드와 포커스

- [ ] 도메인 탭을 방향키·Home·End로 이동할 수 있다
- [ ] 모달이 열리면 포커스가 안으로 이동하고 Tab이 모달 안에서 순환한다
- [ ] 모달을 닫으면 열었던 카드나 관계 항목으로 포커스가 돌아온다
- [ ] 관계 표의 모델명 버튼을 키보드로 실행할 수 있다
- [ ] 접힌 필터 패널의 컨트롤에 Tab으로 도달하지 않는다
- [ ] 포커스 표시가 항상 보인다

## 5. URL 딥링크

주소창에 직접 입력해 복원되는지 확인한다. 라우트는 최대 3단이다.

| 예시                                           | 기대 화면                     |
| ---------------------------------------------- | ----------------------------- |
| `#speakers`                                    | Speaker 탭                    |
| `#speakers/spk-la-k2`                          | 해당 제품 상세 모달           |
| `#speakers/spk-la-k2/amp-la-la12x`             | 제품과 앰프 Split View        |
| `#speakers/spk-la-k2/media~horizontal`         | 제품 이미지 pane              |
| `#speakers/spk-la-k2/amp-la-la12x~media~front` | 관계 pane의 이미지 확대       |

- [ ] 위 형태가 각각 복원된다
- [ ] 존재하지 않는 ID나 4단 이상 해시는 안전하게 정리되고 오류로 남지 않는다
- [ ] 뒤로가기로 상세가 닫힌다

## 6. 표시 선호와 모션

- [ ] OS의 `prefers-reduced-motion`을 켜면 전환 효과가 꺼진다
- [ ] 앱의 모션 끄기 설정도 같은 결과를 만든다
- [ ] 표시 선호를 바꾸고 새로고침해도 초기 깜빡임이 없다

## 7. 콘솔과 네트워크

DevTools를 연 채로 1~6절을 반복한다.

- [ ] 콘솔 오류·경고가 없다
- [ ] CSP 위반 보고가 없다
- [ ] 404 자산 요청이 없다
- [ ] 외부 출처로 나가는 요청이 없다

## 8. 결과 기록

문제를 발견하면 재현 조건(폭, 브라우저, 조작 순서)을 함께 남긴다. 정적으로 고정할
수 있는 계약이면 회귀 테스트에 추가한다.

- CSS 표 구조·반응형 selector → `public/tests/css-layout-contract.test.mjs`
- 색 토큰과 대비 → `public/tests/color-system.test.mjs`
- 카드·상세 DOM 계약 → `public/tests/ui-regression.test.mjs`
- 포커스·ARIA → `public/tests/accessibility.test.mjs`
- 관계 이동 → `public/tests/relation-navigation.test.mjs`

테스트를 추가·수정했으면 다음을 실행한다.

```powershell
npm run test:ui
npm run verify
```
