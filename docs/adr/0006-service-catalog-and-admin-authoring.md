# ADR-0006: 서비스형 카탈로그와 복수 관리자 편집

- **상태**: 채택
- **날짜**: 2026-08-18
- **관련**: [ADR-0001](0001-static-deployment-boundary.md), [ADR-0002](0002-source-and-runtime-layers.md), [ADR-0007](0007-service-technology-stack.md)

## 맥락

카탈로그는 대규모 공식 원본을 보유하며 여러 관리자가 이미지 위치·순서·표시 이름과
다운로드 파일명을 편집해야 한다. 또한 제조사별 시스템 학습과 설계·입찰 문서의
요구조건 기반 후보 탐색을 위해 프로젝트, 요구조건, 조건별 판정과 근거 이력을
관리해야 한다. 향후 공공조달 공고 버전, 실제 적용 사례·장소, 최신 음향 기술과
지원 제품의 관계, 기업 및 제품·기술 연혁도 같은 canonical 지식에 연결한다.
GitHub Pages는 정적 호스팅이고 Git LFS 자산을 직접 제공하지 못한다. 브라우저에
저장소 쓰기 토큰이나 공용 비밀번호를 넣을 수 없다.

## 결정

공개 읽기 화면은 CDN 캐시를 유지하되 데이터와 관리 기능은 서비스 계층으로 이행한다.

- 구체적인 공급자와 런타임 조합은 [ADR-0007](0007-service-technology-stack.md)을 따른다.
- PostgreSQL을 우선 canonical write model로 사용해 제품·속성·관계·미디어 배치,
  프로젝트·요구조건·조건별 평가, 역할·승인·감사 로그를 트랜잭션으로 관리한다.
- R2 또는 동등한 객체 저장소가 공식 원본 이미지와 문서를 해시 기반으로 보존·전송한다.
- GitHub는 코드, migration, 검증된 snapshot과 변경 이력을 보존한다.
- GitHub 로그인 후 `owner`, `maintainer`, `editor`, `reviewer` 역할을 서버에서 판정한다.
- 원본 교체·제품 삭제·출처 변경은 작성자와 승인자를 분리한다. 모든 변경은 이전 값,
  새 값, 작성자, 검토자, 시간과 근거를 기록한다.
- GitHub Pages는 새 서비스 검증이 끝날 때까지만 롤백 수단으로 유지한다.

## 검토한 대안

- 브라우저에 PAT 저장: 비밀 노출과 권한 회수가 어려워 제외한다.
- Pages에서 로컬 비밀번호 사용: 서버 검증이 없어 관리자를 증명할 수 없으므로 제외한다.
- Git을 실시간 다중 사용자 DB로 사용: 충돌·승인·트랜잭션·감사 질의 비용 때문에 제외한다.

## 결과

이번 릴리스에는 미완성 인증·DB 코드를 섞지 않는다. 현재 기준선을 먼저 커밋하고,
서비스 자원과 비밀 설정은 별도 승인된 이행 페이즈에서 만든다. Git snapshot은 운영 DB의
감사 가능한 projection이며 실시간 write model이 아니다.

## 검증

- 역할별 API 권한과 작성자-승인자 분리
- append-only 감사 로그와 idempotency key
- 기존 stable ID·관계·시리즈 순서·미디어 해시의 1:1 migration
- 객체 원본과 source manifest의 SHA-256·바이트·MIME 일치
- 공개 URL·검색·필터·상세 projection의 이전/신규 비교 및 rollback rehearsal

## 재검토 조건

- 관리자가 한 명으로 영구 고정되거나 편집 기능이 폐기될 때
- PostgreSQL·객체 저장소의 용량·질의·지역 요구가 측정 한계를 넘을 때
- 전용 PIM/DAM 도입 비용이 자체 운영 비용보다 낮아질 때
